
## Cross-project goal leak — root cause + fix (PR #52)

**Incident:** `opencode serve` running in agents-supervisor injected this repo's OpenClawBot `Goal.md` checklist as `MANDATORY GOAL` into session `ses_05dee9808ffewDSZj4D3tn8fte` working in KineticAiCoach (no Goal.md). 14-session fan-out wedged the server.

**Two root causes:**
1. `core/reflection-prompt.mjs:76` `readSupervisorFile` fell back to `defaultsDir` for ALL 4 supervisor files. `defaultsDir` = the plugin's OWN `.agents/supervisor` (`supervisor-impl.ts:46`). So every project inherited the plugin repo's Goal.md.
2. `opencode/supervisor-impl.ts:1233` — plugin `directory` is the SERVER cwd, fixed at plugin init, NOT per-session. All per-project reads AND goal writes used it.

**Key facts to remember:**
- Per-session cwd IS available: `AssistantMessage.path.cwd` (`@opencode-ai/sdk types.gen.d.ts:89-92`). New helper `core/session-context.mjs`.
- Write side mattered as much as read side — `writeProjectGoal(directory, ...)` is how one project's goal got written into another project's Goal.md in the first place.
- `supervisorStore` (`.supervisor/goals/`) intentionally stays server-scoped; changing it orphans existing state.
- The `SCOPE GUARD` prose in `.agents/supervisor/Goal.md` is a prod mitigation only; code now enforces scoping.

**Testing lesson:** the E2E harness runs its sessions IN the server cwd, so `sessionDirectory === directory` and wiring bugs of this class are structurally invisible to it. Added a source-text wiring guard in `test/goal-scope.test.mjs` (comments stripped before matching) as the only regression detector.

**Process note:** a delegated subagent lost the B1 edit during a `git stash`/`stash pop` cycle and returned a one-line non-answer ("e2e failing, checking"). Always re-verify subagent worktree state with `git diff` before trusting a completion claim. The reported e2e 500s were transient (disk was 100% full), not a regression.
