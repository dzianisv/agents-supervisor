## Runaway-limit REVISED 64 -> 20 after external research (owner: "base on researches and numbers")

- Owner rejected feel-picked numbers ("why 50, why not 64 or 100?"). Gathered EXTERNAL evidence (research subagent, verified source URLs) to anchor the default.
- KEY unit insight: our supervisor re-injection ≈ ONE FULL AGENT TURN, not an inner ReAct step. Only frameworks counting full turns are comparable.
- Comparable-unit framework defaults CLUSTER AT ~10: OpenAI Agents SDK max_turns=10, AutoGen v0.2 GroupChat.max_round=10. Heavyweight coding agents ship turn cap OFF + use cost budget (Claude Agent SDK max_turns=None; SWE-agent $3/instance). NON-comparable step caps (LangChain 15, smolagents 20, LangGraph 25 super-steps, OpenHands 500) count inner steps.
- Self-correction is front-loaded: Self-Refine ≤4 rounds, Reflexion plateaus, Huang et al. arXiv 2310.01798 (intrinsic self-correction can DEGRADE without new feedback).
- Internal data agrees on HEALTHY: p50=3, p90=3. Neither internal nor external supports 50/64/100 for a turn-counted loop.
- DECISION: default 64 -> **20** = 2× the ~10-turn framework norm, ~6-7× measured healthy median 3, top of evidence-supported band (nothing >~25 has framework support). Kept as pure BACKSTOP behind supervisor_loop_exit + no-progress gate + goal deadline + /supervisor off.
