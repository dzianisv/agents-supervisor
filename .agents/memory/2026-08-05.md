
## GSD (open-gsd/gsd-core) prompt-injection mechanics — research for supervisor plugin

Cloned to /var/folders/gq/.../T/opencode/gsd-core (network OK).

Key findings (file:line):
- GSD ships ONE opencode plugin `.opencode/plugins/gsd-core.js` (782 lines) that is a **thin adapter**: it spawns the existing Claude Code hook scripts under `hooks/*.js` as subprocesses, JSON on stdin, JSON+exit-code on stdout. No logic duplicated per host.
- Hook protocol: exit 2 or `{decision:"block",reason}` → adapter `throw new Error(reason)` (opencode returns error to model). `{hookSpecificOutput:{additionalContext}}` → advisory, pushed to `output.metadata._gsdAdvisory[]` + `console.error`. See gsd-core.js:282-323.
- Injection points wired: `config` (register commands/agents/skills), `tool.execute.before` (5 guards), `tool.execute.after` (content rewrite + injection scan + context monitor), `experimental.session.compacting` (pushes breadcrumb to `output.context`), `event` (session.created / file.edited / session.idle / permission.* / session.error — last three are declared-but-noop sentinels).
- **State across compaction**: `.planning/STATE.md` is the durable store. Slash commands / SKILL.md `@`-include it in the `<context>` block so every command re-injects state. `experimental.session.compacting` pushes a breadcrumb (gsd-core.js:651-655). `gsd-write-guard.js` HARD-BLOCKS a Write that shrinks STATE.md/ROADMAP.md below 40% of on-disk lines (write-guard.js:81,85,308-345) with a path-bound, 15-min TTL, single-use sentinel `.planning/.gsd-allow-shrink` as escape hatch.
- **Skipped-step detection**: `gsd-agent-isolation-guard.js` compares a shell-computed value persisted to `.gsd/dispatch-isolation-sentinel.json` against the args the model actually put in its `Agent(...)` call — blocks if the model didn't copy it. "A prose backstop cannot fix a prose defect."
- **Idempotency**: context-monitor debounces via `/tmp/claude-ctx-{sid}-warned.json` (5 tool calls between warnings, severity escalation bypasses); one-shot `criticalRecorded` flag; adapter's `warnedMissingHooks` Set warns once per hook file; advisories ACCUMULATE into an array (never clobber).
- **Toggles**: everything keys off `.planning/config.json` — `hooks.context_warnings` (default true), `hooks.workflow_guard` (default false), `hooks.community` (default false, gates the .sh hooks). Adapter hoists the config read IN-PROCESS to skip the subprocess spawn entirely when disabled (gsd-core.js:257-266).
- **Capability system**: `capabilities/*/capability.json` declares `contributions`/`steps`/`gates` at named workflow extension points (`plan:pre`, `execute:post`, ...) with `when:` config-key predicate and `onError: skip`. Fragments are `.md` files injected verbatim into a named role's context. Dispatch contract: gsd-core/references/loop-hook-dispatch.md.

Gap worth noting for our plugin: opencode has no first-class "inject text into the model's next turn" for tool hooks — GSD settles for `output.metadata` + stderr, which is NOT guaranteed to reach the model. Only `experimental.session.compacting` has a real `output.context[]` array.
