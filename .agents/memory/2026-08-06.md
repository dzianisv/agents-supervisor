
## agents-supervisor: feat/status-diagram merge (4-branch composition)

Merged `feat/status-diagram` into main on top of `fix/supervisor-off`, `fix/task-context`, `fix/goal-lifecycle`. Commit 913e043 (local only, NOT pushed).

Semantic conflicts the textual merge could not catch — worth remembering as a class:

1. **A function that unconditionally decorates its output kills a guard that inspects that output.** `buildEscalatingFeedback` appends the status directive to every message; `hasFeedbackBody` then could never return false. Fix: `stripStatusDirective` before the body check.
2. **A feature toggle added on one runtime is a half-truth until every injection path honours it.** `/supervisor:status off` gated only the Claude Code autopilot nudge. Fix: `buildEscalatingFeedback({ statusDirective })`, both runtimes pass `isStatusDiagramEnabled(state)`.
3. **In-memory caches are empty after a restart.** `shouldInjectStatusDirective` read the session's project dir from `sessionDirCache` → a restarted server read the SERVER cwd's `.supervisor/disabled` for every pre-existing session. Fix: persist `SupervisorState.projectDir`, read it from the store load the gate already does.
4. **An early `return` added to a branch orphans anything appended after it.** The status-compliance correction returns out of the completion path; goal retirement had to move BEFORE it.
5. **A test that asserts the old behaviour is a merge hazard.** `test/e2e-cc.mjs` asserted `goal.status === 'achieved'`; `fix/goal-lifecycle` had already changed that to "goal is cleared" and nobody re-ran e2e-cc. It was broken on main before this merge.

New coverage: `test/status-goal-composition.test.mjs` (23 cases). Verified 5 of them fail on the naive union before declaring them useful.

## Supervisor plugin — 30-day forensic pass (PR #61)

Mined 962 real supervisor injections from `~/.local/share/opencode` (opencode) and
`~/.claude/projects` (Claude Code). Report: `.scratch/supervisor-misfires.md`.

Findings, by observed volume — none of these were what we guessed up front:

| Bug | Count | Root cause |
|---|---:|---|
| Supervisor ran inside **subagent** sessions | 633 (66%) | `runSupervisor` never checked `session.parentID` |
| Judge blamed the agent for the **supervisor's own** `slice(0,4000)` | 169 | no truncation marker; two extractors disagreed |
| `/supervisor off` silent no-op | 3 of 5 | `mode` branch evaluated before `action`, early-returned |
| Content-free verdict looped to the retry cap | 38 (one 15x) | empty verdict still set `shouldContinue` |
| Stale goal / stale task | ~135 | `taskSummary` = every user turn ever; `Goal.md` MANDATORY forever |

Facts worth keeping:
- SDK field for a child session is **`parentID`** (SQLite stores `parent_id`).
  `message.info.parentID` is a MESSAGE id — never derive subagent-ness from it.
- Tool output lives at `part.state.output` (string) when `part.state.status === "completed"`;
  errors at `part.state.error`. The supervisor never read either before this PR.
- opencode 1.17.9 registers `experimental.chat.system.transform` as a **flat dotted key**
  (`hooks["experimental.chat.system.transform"]`), NOT a nested object. Nested never fires.
  It fires **twice per user turn** → idempotency is mandatory.
- The opencode tool JSON schema marks every param **required** even when zod says `.optional()`,
  so the model is forced to emit filler values. Executors must treat `""`/`"null"`/`"undefined"`/`null`
  as absent.
- Claude Code path was **inert**: 0 injections across 27,080 transcripts despite being enabled.
- `test/e2e-cc.mjs` was already broken on main and nobody had re-run it. Four parallel branches each
  passed alone and broke 5 semantic invariants on merge with **zero textual conflicts** —
  hence `test/status-goal-composition.test.mjs`.

Process note that worked: 3 parallel worktrees (one per bug cluster) + a dedicated
merge-and-reconcile subagent that hunted semantic conflicts the merge could not see.

## fix/session-state-layout — per-session state consolidation (pushed, not merged)

- Per-session machine state now lives at `.supervisor/sessions/<full session id>/{state.json,verdicts.jsonl}`. Project config `.agents/supervisor/*` untouched, NOT sharded.
- `core/session-store.mjs` is the ONE accessor. `goalStore` = behavioural facade, `supervisorStore` = async adapter. No third implementation.
- Fixed the real bug: `.supervisor/current_session` is shared, so `/supervisor off` hit the last session to stop. Resolution order is now `--session` (prefix-expandable) → `$SUPERVISOR_SESSION_ID` (hook stdin) → `$CLAUDE_SESSION_ID` → `current_session` (announced). Ambiguous → list candidates, act on none, exit 1.
- Trap found while doing it: moving `attempts` into `state.json` created a lost-update path — the hook read `goalState` before `writeAttemptCounter`, then `save()` clobbered the counter. Drove `goal.attempts` to 1 instead of 7. Every whole-state `save()` on a hot path in BOTH runtimes is now `mutate()` (locked RMW). `test/goal-per-turn.test.mjs` is the guard.
- Atomic write (temp+rename, 0600 from creation) is NOT sufficient alone — it stops corruption, not lost updates. Hence the O_EXCL lock with a 10s stale breaker.
- GC: >30 days untouched, cap 200, throttled to once/day per project, best-effort, protects the live session.
- Tests: 613 pass in `test/*.test.mjs`, 14 in e2e-opencode alone, 11 in e2e-cc. NOTE `test/*.test.mjs` already globs `e2e-opencode.test.mjs` — running both commands back-to-back races two servers; pause between them.
