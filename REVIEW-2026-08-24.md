# Architectural Review — agents-supervisor (2026-08-24)

Scope: two-mode supervisor architecture (`autopilot` / `reflection`), the `goal`
attribute, dead code from the 3-mode migration, complexity hotspots, test
coverage, and quick wins. Read-only review — no code changed. Methodology:
full read of `core/goal.mjs`, `core/turn-classifier.mjs`,
`core/session-store.mjs`, `opencode/supervisor-impl.ts`, `bin/supervisor.mjs`,
`bin/supervisor-on-stop.mjs`, `bin/plainspeak-on-stop.mjs`, `AGENTS.md`, plus
grep-verified cross-checks (not guesses) for every dead-code / duplication
claim below.

---

## 1. Mode boundary correctness — **clean**

The two-mode migration documented in `AGENTS.md` is real and appears
correctly finished, not aspirational:

- `SUPERVISOR_MODES = ['autopilot','reflection']` (`core/goal.mjs:42`) and
  `SupervisorMode = "autopilot" | "reflection"` (`opencode/supervisor-impl.ts:285`)
  agree; `resolveSupervisorMode` (`core/goal.mjs:84-92`) never returns
  `'goal'`.
- `shouldSkipReflection` (`core/turn-classifier.mjs:172-179`) checks
  `isSupervisorControlTurn` first, then `hasActiveGoal`, then
  `mode==='autopilot'` — ordering matches the documented rule and is the only
  place ordering matters.
- Grepped every `mode === 'goal'` / `mode: 'goal'` occurrence repo-wide
  (`opencode/*.ts`, `core/*.mjs`, `bin/*.mjs`): every hit in *production* code
  is either (a) `core/session-store.mjs:245,286` — the one documented
  migration site in `normalizeLoadedState`, or (b) a comment explaining why
  the check is gone. No live `if (mode === 'goal')` branch exists outside
  migration/alias-mapping code. This part of the migration is genuinely done,
  not vestigial.
- The `'goal'` **input alias** (`bin/supervisor.mjs`, opencode
  `requestedMode==="goal"`) is intentionally retained per AGENTS.md — correctly
  scoped to the command-parsing boundary only, and `goalStore.setMode` still
  throws on it (verified: the alias mapping lives at the command surface, not
  in the store).

**One residual inconsistency worth a decision, not a bug:** `bin/supervisor.mjs`
accepts `'goal'` as an alias for `set-goal` at the top-level command dispatch
(`core/goal.mjs:313`: `if (lower === 'set-goal' || lower === 'goal') return
parseSupervisorCommand('set-goal', tail)`), i.e. `'goal'` is overloaded to mean
two different things depending on argument position — a *mode* alias in one
context and a *subcommand* alias in another. Both are individually documented
and tested, but nothing enforces they can't collide (e.g. `/supervisor goal
autopilot` is ambiguous between "set mode to autopilot via the goal alias" and
"set goal condition to the literal string 'autopilot'"). Low priority — no
evidence of confusion in the test suite or AGENTS.md history — but worth a
one-line comment at the `'goal'` dispatch site cross-referencing the mode-alias
one so a future reader doesn't "clean up" one without noticing the other.

**Verdict: no changes needed here.** This is the one area of the four review
axes where the migration claims in AGENTS.md hold up under grep-verification.

## 2. Dead code / duplication

### 2a. `bin/supervisor-on-stop.mjs` vs `bin/plainspeak-on-stop.mjs` — confirmed, concrete duplication

Grep-verified identical or near-identical function **names** across both
files (not just similar logic — the same identifiers, meaning any future core
extraction is a rename, not a redesign):

| Function | supervisor-on-stop.mjs | plainspeak-on-stop.mjs | Same logic? |
|---|---|---|---|
| `sanitizeCwd` | L110 | L60 | **No — diverges silently.** Supervisor version `throw`s on an invalid/non-absolute cwd; plainspeak version returns `null`. Same name, same apparent contract, different failure mode. This is exactly the "two copies disagree" bug shape AGENTS.md warns about elsewhere (§ "per-session state", `sessionStore` note). |
| `readTranscriptTail` | L218 | L77 | Same purpose (bounded tail-read of a transcript file), separately implemented. |
| `endsWithTrailingQuestion` | L130 | L125 | Same purpose, separately implemented. |
| `computeTurnKey` | L152 | L150 | Same purpose (turn-scoped dedup key), separately implemented — and `core/goal.mjs`'s own doc comment on `decideGoalTransition` already worries about exactly this kind of "second, independently-incremented tally" class of bug (goal.mjs:414-421, re: issue #57). This is the same failure class, just not yet bitten. |
| `debug` | L98 (exported) | L51 (not exported) | Same purpose, near-identical body. |
| `readStdin` | L713 | L315 | Same purpose, almost certainly line-for-line identical (stdin→string collection is not something that varies). |

**Proposed diff (concrete, not hand-wavy):**
1. Create `core/transcript.mjs` (or extend `core/task-context.mjs`, which
   already owns `extractLastAssistantText`/`buildConversationChain` — see
   AGENTS.md's "ONE extractor" precedent) exporting: `readTranscriptTail`,
   `normalizeTranscriptToMessages` (already only in supervisor-on-stop, but is
   a transcript primitive plainspeak likely needs a version of too — check),
   `endsWithTrailingQuestion`, `computeTurnKey`, `sanitizeCwd`, `readStdin`.
2. Decide the ONE contract for `sanitizeCwd` (throw vs. return-null) before
   merging — this is the one place the two implementations actually disagree,
   so it needs an explicit decision, not a silent pick of whichever wins the
   merge.
3. Both `bin/*-on-stop.mjs` files import from the new core module instead of
   defining their own copies. Net effect: both files get thinner (target:
   `plainspeak-on-stop.mjs` under 350 lines, `supervisor-on-stop.mjs` under
   1250), and the `sanitizeCwd` contract divergence — currently a live bug
   waiting to be exercised — is eliminated for good instead of forked twice.
4. Do this LAST relative to other cleanups here since it touches a
   pre-commit-gated file (`opencode/` E2E gate doesn't cover `bin/`, but
   `test/hook.test.mjs`, `test/foreign-stop-hook.test.mjs`, and
   `test/plainspeak-hook.test.mjs` do — run those after extraction, not just
   the opencode E2E).

### 2b. `core/goal.mjs` vs `opencode/supervisor-impl.ts` — NOT duplicated, correctly shared

This looked like a likely duplication site per the task brief, but it isn't:
`opencode/supervisor-impl.ts:83` re-exports `resolveRunawayLimit,
parseSupervisorCommand, buildGoalRequirementSection, decideGoalTransition,
resolveSupervisorMode, DEFAULT_SUPERVISOR_MODE` straight from `core/goal.mjs`
rather than reimplementing them, and `AGENTS.md`'s own framing (`goalStore` /
`supervisorStore` as "a behavioural facade and an async-signature adapter…
not two implementations of one on-disk contract") matches what the code
actually does. **No action needed** — this axis of the brief's suspicion did
not pan out under inspection, worth noting explicitly so it isn't re-litigated
next review.

### 2c. `.supervisor/` test fixtures — already clean

`.gitignore` already excludes `.supervisor/`, `.dataset/`, `.tasks/`,
`.plainspeak/`, and `*.jsonl` (with two explicit example-file exceptions).
`git ls-files | grep -i supervisor` returns nothing under `.supervisor/`.
**No stale fixtures are committed.** This concern in the task brief does not
apply to the current tree — also worth noting so it isn't chased again.

### 2d. Small dead-code candidate

`core/model-selection.mjs` (71 lines) has **zero** references from any
`test/*.test.mjs` file (grep-verified: every other `core/*.mjs` file has at
least one referencing test file). It IS imported by `opencode/supervisor-impl.ts`
and `core/session-context.mjs`, so it's live code, just untested — see §4,
not a delete candidate. Listed here because "no tests" and "no longer used"
are easy to conflate; this is the former, not the latter.

## 3. Complexity hotspots

### `opencode/supervisor-impl.ts` (3614 lines) — top candidates for extraction to `core/*.mjs`

The file already extracts a lot to `core/` (goal, task-context, feedback,
evaluation, etc. are all re-exported/imported, not reimplemented) — the
remaining bulk is concentrated in a few places:

1. **`runCrossModelReview`** (starts ~L1428, body runs to near EOF —
   awk-measured "2186 lines" is inflated by counting to end-of-file since it's
   the last top-level function before the plugin's closing braces, but even a
   conservative read puts it at several hundred lines of actual body before
   the plugin-registration boilerplate). This function mixes model-list
   parsing, LLM invocation, response parsing, and side-effecting state writes
   in one body. **Proposed split:** pull the pure parsing/decision pieces
   (`parseRoutingFromYaml`, `parseModelListFromYaml`, `parseRoutingCategory` —
   these are ALREADY separate functions, just not yet moved) into
   `core/model-routing.mjs`, leaving `runCrossModelReview` itself as the thin
   orchestration shell the architecture doc calls for. This directly grows
   `test/model-routing-regression.test.mjs` coverage without touching the
   runtime adapter.
2. **`loadConfiguredSuperviseSubagents`** (L241, 273 lines) — config-file
   parsing + fallback-tier resolution logic that is pure I/O + parsing, no
   opencode-SDK dependency visible in its signature. Candidate for
   `core/config-loader.mjs` alongside `readConfiguredMaxAttempts`
   (`core/goal.mjs`), which already does the equivalent job for
   `maxAttempts:` — these two config readers currently live in different
   files with different ownership, despite parsing the same YAML file format
   for sibling settings. Consolidating them is also a §2 duplication fix, not
   just a hotspot fix.
3. **`loadRubric`** (L514, 138 lines) — precedence-resolution logic
   (session > project > shipped) duplicating a pattern `core/session-store.mjs`
   already names and owns for state precedence. Worth checking whether the
   precedence *algorithm* (not the rubric content itself) can share a helper
   with `resolveSupervisorPromptPrecedence` (L736, already a separate function
   in the same file) — two independently-hand-rolled precedence walks in one
   file is itself a smell.
4. **`buildTaskContext`** (L1165, 74 lines, async) — has a same-named
   sync counterpart in the OTHER file under review,
   `buildTaskContextFromTranscript` (`bin/supervisor-on-stop.mjs:565`, 67
   lines). AGENTS.md documents `extractLastAssistantText`/
   `buildConversationChain` as already unified in `core/task-context.mjs`, but
   these two `buildTaskContext*` functions building the SAME shape
   (`TaskContext`) from two different message representations (opencode SDK
   messages vs. CC transcript messages) are not. Worth checking whether they
   can share a normalization step ahead of a common builder in
   `core/task-context.mjs` — same risk shape as the `computeTurnKey` /
   `sanitizeCwd` duplication in §2a, just across the opencode/CC boundary
   instead of within the CC side.
5. **`analyzeSelfAssessmentWithLLM`** (L1239, 99 lines) — already flagged
   once in AGENTS.md's own history (`isActionlessVerdict` was "unreachable on
   the opencode runtime" because this function substitutes
   `verdict.feedback || "Judge analysis completed"` before the guard sees it —
   a bug born from exactly this kind of oversized function doing parsing +
   substitution + guard-input-shaping in one body). Given it already produced
   one silent bug of this shape, it is the single highest-value function in
   this file to shrink and cover directly with a focused unit test file
   (currently covered only indirectly via `test/goal-lifecycle.test.mjs` per
   AGENTS.md's own note).

### `bin/supervisor-on-stop.mjs` (1406 lines) — top candidates

1. **`main`** (L723, 683 lines — nearly half the file). This is the classic
   "thin runtime adapter" that isn't thin: dispatch, config loading, judge
   invocation, verdict writing, and goal-transition side effects are all
   inlined in one function body instead of being thin calls into `core/`
   primitives (most of which already exist — `decideGoalTransition`,
   `describeRunawayLimit`, `resolveSupervisorMode` are all imported from
   `core/goal.mjs` already). The opportunity here is not "write new core
   logic," it's "`main` already calls the right core functions but also does
   a lot of INLINE work between those calls that could be named helper
   functions in this file first, then promoted to `core/` once duplicated
   with `plainspeak-on-stop.mjs`'s `main` (325 lines, same shape, smaller)."
2. **`buildFakeAssessment`** (L632, 81 lines) — test/fixture-support code
   living in the production Stop-hook script rather than in
   `test/helpers/`. Grep to confirm before moving: if only used by tests,
   this is a pure quick win (§5) to relocate; if the fake path is also a
   production fallback (e.g. `SUPERVISOR_FAKE_JUDGE`), it stays but should be
   isolated behind a clearer boundary so it's obviously test-support code at a
   glance.
3. **`collectDeliveredMedia`** (L462, 70 lines) + **`scanTranscriptForMedia`**
   (L378, 57 lines) + **`tryExtractVideoFrame`** (L438, 24 lines) — three
   functions, one concern (media detection/extraction from a transcript),
   currently living inline in the Stop-hook script with no core-module home
   and no dedicated test file (`test/media-resolver.test.mjs` exists — verify
   it covers these three specifically, or it's a coverage gap per §4).
   Natural `core/media-resolver.mjs` extraction given the existing test file
   name already assumes this module exists.

### One gap worth flagging specifically: `sanitizeCwd` divergence (§2a) has no test that would catch it

Neither `bin/supervisor-on-stop.mjs`'s nor `bin/plainspeak-on-stop.mjs`'s

assert on `sanitizeCwd` by name). This is exactly the kind of two-copy drift

## 5. Quick wins (prioritized, smallest/safest first)

1. **Consolidate `sanitizeCwd`** (§2a) into one function with one explicit
   contract, used by both Stop-hook scripts. Highest priority of the "quick"
   wins because it's currently a silent behavioral divergence, not just
   duplicated code — genuinely a correctness fix disguised as a cleanup.
2. **Extract `readStdin`** (near-certainly identical in both files) to
   `core/stdin.mjs` or similar — zero behavior risk, pure line-count win.
3. **Extract `debug`/`endsWithTrailingQuestion`/`computeTurnKey`/
   `readTranscriptTail`** as a batch into one new `core/transcript.mjs` (§2a
   full proposal) — do this as ONE PR after #1 and #2 land and are proven
   green, not combined with them, so a regression is bisectable to a single
   function.
4. **Move `buildFakeAssessment`** (`bin/supervisor-on-stop.mjs:632`) to
   `test/helpers/` if grep confirms it's test-only (§3, item 2) — pure
   relocation, no logic change.
5. **Add a direct unit test file for `core/model-selection.mjs`** (§4) —
   smallest actual "add," not "remove," on this list, but cheap insurance
   given the sibling-function bug history in this exact area
   (`analyzeSelfAssessmentWithLLM`'s substitution bug).
6. **Add a one-line cross-reference comment** between the `'goal'` mode-alias
   dispatch (`bin/supervisor.mjs`) and the `'goal'` subcommand-alias dispatch
   (`core/goal.mjs:313`) so a future "let's simplify the alias handling"
   pass doesn't merge two things that only look like one thing (§1).
7. **Consolidate the two YAML config readers** (`readConfiguredMaxAttempts`
   in `core/goal.mjs` and `loadConfiguredSuperviseSubagents` in
   `opencode/supervisor-impl.ts`) behind one `core/config-loader.mjs` (§3,
   item 2) — larger than the above but still behavior-preserving if done as a
   pure extraction with existing tests as the safety net.

## If I only fix 3 things

1. **Fix the `sanitizeCwd` throw-vs-null divergence** between
   `bin/supervisor-on-stop.mjs` and `bin/plainspeak-on-stop.mjs` — it's a real
   behavioral bug hiding as duplicated boilerplate, and it's currently
   untested on either side.
2. **Extract the shared Stop-hook primitives** (`readTranscriptTail`,
   `computeTurnKey`, `endsWithTrailingQuestion`, `readStdin`, `debug`) into
   one `core/` module used by both `bin/*-on-stop.mjs` scripts — this is the
   single biggest, lowest-risk line-count and drift-risk reduction available,
   and it's a mechanical extraction backed by existing hook test files.
3. **Split `runCrossModelReview` and `analyzeSelfAssessmentWithLLM`** out of
   `opencode/supervisor-impl.ts` into `core/model-routing.mjs` — not because
   they're the biggest by line count, but because `analyzeSelfAssessmentWithLLM`
   already produced one real, shipped bug (`isActionlessVerdict` unreachable
   on opencode) from exactly this kind of oversized, untested,
   multi-concern function body, and it currently has no dedicated test file
   of its own to prevent a repeat.

The good news, stated plainly: the thing this review was most worried about
finding — vestigial 3-mode (`goal`) dead code left over from the migration —
**is not there**. The migration documented in AGENTS.md is real and matches
the code. The actual cost centers are the Stop-hook duplication (§2a) and a
handful of oversized, under-tested functions in `supervisor-impl.ts` (§3) —
both are mechanical, low-risk cleanups, not architecture changes.
