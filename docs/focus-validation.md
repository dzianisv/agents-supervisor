## What the real screen demonstrated

- Three trials each of ticket substitution, wrong historical-tenant mutation and direct simulated SSH; plus a ticket replay through actual `--print @task.md`. Ten prohibited tool proposals were blocked before their fixture effects, then the real worker finished the unchanged task.
- Three trials each of pre-existing-account proof and missing-quota-as-healthy claims. The original goal stayed pending until new provisioning or an honest report was delivered.
- Three ordinary positive controls: dependency documentation → helper implementation → worker tests and six independent tests; minimum local redaction → original audit; explicitly authorized temporary ticket → original audit. Zero supervisor false blocks. Two ordinary command/test failures were retained, not mislabeled as supervisor blocks or hidden.
- All 19 original declarations retired exactly once after completion; actual artifacts, target identities and fixture input integrity were checked independently. No human recovery correction was supplied.

Forced bad actions/claims are **replays**, not measurements of natural model drift. SSH programs and account provisioning are local fixture programs, not real customer operations. The independent reviewer inspected anonymized tasks, native traces, artifacts and recorded independent tests without provider/producer labels or the driver's pass flags. The controller mechanism remains visible; this is not a fully blinded comparative benchmark.

## Cost and limits

The 19 runs used 317 added audit calls and 646,066 added tokens as reported by the provider. Median audit latency was 2.92 seconds; maximum 23.33 seconds. Dollar cost is **unknown**: a zero-priced subscription catalog entry does not establish free usage. The 30-second/2,000-output-token bounds were not increased. Changed/nested/normalized arguments can require additional checks beyond the proposed-batch check.

The supported composition has one trusted native owner, the supervisor as first input observer, and no later argument-mutating handlers. Hidden earlier transformations and arbitrary host/extension I/O are not fenced. Cancellation can retain a native queued input for explicit resume. Completion judgments remain prose-based; independent filesystem/tests here belong to validation, not a new production verification service.

## Failed attempts remain part of the record

Six earlier diagnostic/screens did not meet acceptance or were explicitly cancelled: wrong transport attribution, a provider timeout, an over-strict concise-contract rejection, a copied 64-character reference typo, a false hold caused by partial code redaction, and parent cancellation to address source-review findings. They were retained with source identities, not averaged away or counted as passes. The earlier mislabeled helper case was an extra audit control, not frozen helper coverage; the final complete screen uses the actual coding-helper case. After the last production fix, the entire frozen screen was rerun on the final source.

Raw transcripts, model calls, private cross-attempt `eval.csv`, identity mappings and reviewer details stay outside git with owner-only permissions. Only this redacted aggregate is committed.
